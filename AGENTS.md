# AGENTS.md

## Project shape

- This is a single Python package, not a monorepo. Runtime code is under `src/dataguard`; tests are under `tests`; documentation is under `docs`; documentation examples are sourced from `notebooks`.
- The distribution is named `peh-dataguard`, but the import name is `dataguard`. The public exports are `Validator`, `Filter`, and `ErrorCollector` from `src/dataguard/__init__.py`.
- Python `>=3.10` is supported; CI tests Python `3.10` through `3.14`. Ruff targets Python 3.10, so do not use syntax or APIs newer than the minimum unless the project metadata is changed.
- The main flow is configuration mapping -> recursive Pydantic expression/schema models -> Polars expression compilation -> Pandera validation for `Validator` or direct Polars filtering for `Filter`. The relevant wiring is in `config/config_reader.py`, `core/check/`, `core/filter/`, and `core/models/`.
- `CaseCheckExpression` is recursive: `conjunction` and `disjunction` require at least two expressions, while `condition` requires exactly two. Built-in check names are mapped to Polars methods; custom callable checks are supported for validation, not filtering.
- `Validator` normally collects Polars/Pandera/configuration errors in the shared `ErrorCollector`; pass `collect_exceptions=False` when an exception should propagate. `Filter.apply` preserves `DataFrame` versus `LazyFrame` input type.

## Toolchain and commands

- Use `uv` and commit `uv.lock` changes generated by `uv lock`; do not edit the lockfile by hand. The direct dependency bounds intentionally block next-minor releases while allowing patch updates.
- Reproduce the CI environment with `uv sync --locked --all-extras --dev`. The docs environment is separate: `uv sync --locked --no-default-groups --group docs`.
- Run the full test and coverage suite with `make test` (it runs `uv run pytest -s -vv --cov=src/` and then `coverage html`). It modifies the tracked `.coverage` file; restore it before committing unless the coverage data is an intentional change.
- Run a focused test with `make test-set SET='tests/tests_filter/test_filter.py::test_filter_apply_dataframe'`, or use `uv run pytest` with the desired node id. Tests are local/unit-style and use Hypothesis; no external service is configured.
- Run lint with `make lint`. It runs Ruff checks twice; it does not check formatting. For a non-mutating formatting check use `uv run ruff format --check .`. `make format` runs Ruff autofixes and formatting, so it changes files.
- `bash scripts/pre_commit.sh` is the repository wrapper for `format -> lint -> test`; it is mutating because it runs the formatter first. There is no configured mypy/pyright type-check step.
- Build the sdist and wheel with `uv build`. Keep `dist/`, `site/`, `htmlcov/`, caches, and virtual environments out of commits.

## State and testing gotchas

- `ErrorCollector` is cached/shared; clear it between tests that inspect collected reports. The validator test fixture demonstrates this cleanup.
- `parse_checks()` destructively pops `name`, `error_level`, and `error_msg` from each check mapping. Do not reuse an input mapping after parsing if its original contents matter.
- `expression_mapper` is global and `map_command()` mutates parsed expression objects. Filter tests reset this mapping; preserve that isolation when adding tests or changing command registration.
- `CaseCheckExpression` and `SimpleCheckExpression` are the backend-neutral expression layer. Keep built-in lowering shared between validation and filtering rather than duplicating command logic.

## Documentation and release operations

- Zensical, not the `mkdocs` CLI, builds the site from the MkDocs-compatible `mkdocs.yml`. Use `make serve` for a local preview and `bash scripts/docs_build.sh` for the strict clean build; the script uses `uv run --no-default-groups --group docs` and builds `site/`.
- The Markdown guides embed code with `--8<--` snippets from `notebooks/`. Edit the notebook source and rebuild rather than copying code into the generated guide. `docs/changelog.md` similarly includes the root `CHANGELOG.md`.
- API documentation is generated from source docstrings through `mkdocstrings` (`paths: [../src]`), so update the relevant source docstrings when changing public APIs.
- The `DOCS` workflow runs only for pushes to `master` and deploys the built `site/` directory through GitHub Pages Actions. GitHub Pages must be configured to use GitHub Actions as its source.
- The publish workflow builds on branch pushes, publishes to TestPyPI on tag pushes, and publishes to PyPI when a GitHub release is published. A normal branch push alone does not publish the package.
- For a release, update `project.version` in `pyproject.toml`, regenerate `uv.lock`, run `uv build`, and tag the matching commit; do not create a release with mismatched project and lock metadata.
- `presentation.md` is a standalone 16:9 Marp deck; no Makefile or CI target renders it, so validate it separately if it is changed.
